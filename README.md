# Pharma Cold-Chain Data Warehouse & BI Pipeline

An automated data-engineering pipeline for a pharmaceutical cold supply chain, built for the course
*Intelligent Data Architectures* (Fall 2026). Apache Airflow orchestrates ingestion, staging,
dimensional modelling, an analytical query layer and BI dashboards; every layer is monitored on its
own dashboard.

| Layer | Technology |
|---|---|
| Orchestration | Apache Airflow 2.10 (LocalExecutor) |
| Ingestion | Python REST API (Flask/gunicorn) + file-watcher (watchdog), micro-batch stream simulator |
| Staging / ODS and metrics | PostgreSQL 16 (`stg`, `ops`, `mart` schemas) |
| Data mart (star schema) | DuckDB 1.1 |
| BI and observability | Grafana 11 |
| Packaging | Docker Compose |

## Architecture

```
 generator DAG --.xlsx--> data/landing/ --file-watcher--> ingestion API --> Postgres  stg.*   (staging / ODS)
                                                                 |  every load logged -> ops.batch_load_log
 stream DAG --micro-batches (1/s)-------------------------------> stg.iot, ops.stream_metrics
                                                                 v
   p1_ingest_monitor (every minute) -> new loads waiting? -> triggers
                                                                 v
   p1_transform:  extract -> dims (SCD2) -> facts -> aggregates -> data-quality checks -> publish -> mark loads done
                                   DuckDB star schema                      Postgres mart.* (BI)
                              \-> p1_query_layer (timed queries)   \-> p1_storage_metrics (rows, MB, coverage)
   Grafana: 4 observability dashboards read the ops.* tables
```

## Quick start

Requirements: Docker Desktop (4 GB+ RAM allotted), 10 GB free disk. Works on macOS, Linux and Windows.

```bash
# 1. place 01_master_data.csv, 05_pharmacy_sales_data.csv and 06_hospital_demand_data.csv in data/raw/
make up        # build and start all services (first run: several minutes)
make seed      # drop the historical files into data/landing/  (watch: make logs)
make verify    # reconcile staging vs warehouse
```

| Service | URL | Login |
|---|---|---|
| Airflow | http://localhost:8080 | admin / admin |
| Grafana | http://localhost:3000 | admin / admin |
| Ingestion API | http://localhost:8000/health | - |

- **Refresh the warehouse:** Airflow -> `p1_generate_data` -> *Trigger DAG w/ config* -> `{"refresh_no": 1}` (then `2`).
  New files land as `.xlsx`, are ingested automatically and flow through to the warehouse and dashboards.
- **Run the stream:** `make stream` (or trigger `p1_stream_ingest`; parameters `duration_sec`, `rate_eps`).
- **Reset everything:** `make reset`.

## Repository layout

```
dags/                  Airflow DAGs (thin; logic lives in include/)
  p1_generate_data       data oversampling
  p1_ingest_monitor      detects newly loaded files, triggers the transform
  p1_transform           staging -> star schema -> quality checks -> publish
  p1_query_layer         timed dashboard queries and optimisation benchmark
  p1_storage_metrics     row counts, storage footprint, date coverage
  p1_stream_ingest       streaming-ingestion simulation
include/
  common/                configuration, DB helpers, step logging
  generator/             oversampling script
  ingestion/             schemas, validation, loader, REST API, file-watcher
  streaming/             stream simulator
  dwh/                   DuckDB star schema: DDL, dimension and fact loads, quality checks, publish
  queries/               analytical queries (raw / optimised / partitioned variants) and runner
  metrics/               storage metrics
  sql/init/              Postgres schemas and ops tables
grafana/                 datasource, provisioning and dashboard JSON (generated by build_dashboards.py)
scripts/                 verification and helper scripts
excel/                   DWH design workbook (Phase 1)
docs/                    reports and documentation
```
